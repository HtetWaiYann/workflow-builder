# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Essential commands

All commands run from the repo root unless noted.

```bash
# Install everything (all workspaces)
npm install

# Must run before starting backend or frontend for the first time,
# and after any change to packages/shared/src/
npm run build:shared

# Dev servers (each needs its own terminal)
npm run dev:backend    # http://localhost:3001
npm run dev:frontend   # http://localhost:5173

# Watch shared for changes (third terminal, optional)
npm run dev --workspace=packages/shared

# Type-check frontend (no emit)
cd packages/frontend && npx tsc -b

# Lint frontend
cd packages/frontend && npx eslint .

# Build everything for production
npm run build
```

## Architecture

npm workspaces monorepo. Three packages under `packages/`:

- **shared** — TypeScript-only library. Exports types, interfaces, and constants consumed by both backend and frontend. Compiles to `dist/` (CommonJS). `main` points to `dist/index.js`, so it **must be built** before the other packages can import it.
- **backend** — Express 4 REST API. Runs with `ts-node-dev` in dev (CommonJS, `module: "CommonJS"`). Imports from `@workflow-builder/shared` via the workspace symlink at `node_modules/@workflow-builder/shared → ../../packages/shared`.
- **frontend** — React 19 SPA. Vite 8, TypeScript 6, bundler module resolution, `noEmit: true`. React Compiler is active via `@rolldown/plugin-babel` + `reactCompilerPreset()` in `vite.config.ts` — do not write `useMemo`, `useCallback`, or `React.memo` manually.

The root `tsconfig.json` is a minimal base (target, strict, esModuleInterop). Backend and shared extend it and add `module: "CommonJS"`. The frontend does **not** extend it — it has its own `tsconfig.json` (references) → `tsconfig.app.json` + `tsconfig.node.json` generated by Vite.

## Key constraints

- **Node 24** required (`node:util`'s `styleText` and other APIs used by dev tooling).
- `erasableSyntaxOnly: true` in the frontend tsconfig — avoid TypeScript `enum`, `namespace`, and constructor parameter properties in frontend code.
- `verbatimModuleSyntax: true` in the frontend — use `import type` for type-only imports.
- `noUnusedLocals` and `noUnusedParameters` are enforced in the frontend.
- The backend uses CommonJS; avoid ESM-only packages there.
